# 0.12.1 — 2026-11-21

## Added

- **`brapi_find_studies` `variables`** filters studies by `observationVariableDbIds`. It is verified by count, with a warning when the unfiltered total is not larger. `brapi_federated_find` study searches accept it too. ([#130](https://github.com/cyanheads/brapi-mcp-server/issues/130))
- **`brapi_export_genotype_matrix` `variantDbIds`** (alias `variantDbId`) restricts the export to chosen variants, so a capped export can be re-run in batches. Calls for other variants are left out with a warning when the server ignores the filter. ([#129](https://github.com/cyanheads/brapi-mcp-server/issues/129))

## Changed

- **`brapi_export_genotype_matrix`** warns when the `/variants` metadata scan stops at its row cap, and a pull ended by the call cap or deadline points to `variantDbIds`, naming the call set it ended at when the pull cut that call set short.
- **`brapi_find_genotype_calls`** names all five accepted filters (`variantSetDbId`, `variantSetDbIds`, `germplasmDbIds`, `callSetDbIds`, `variantDbIds`) in its description and no-filter error.
- **`brapi_find_germplasm`** words a free-text scan over a collection that stopped early by the distinct rows collected.
- **Routes escalated to POST `/search`** no longer carry the dialect's "only the first value" downcast warning, since POST sends every value.
- **`extraFilters`** keys whose column holds no string value on any returned row are reported as unverified.
- **Scoped-count warnings** say the filter can't be confirmed when the scoped and unfiltered totals match, no longer asserting the upstream ignored it.
- **`brapi_submit_observations`** checks the apply-mode `studyObservationCount` against an unfiltered baseline and omits it with a warning when the server can't scope `/observations` to the study.
- **`brapi_meta_analysis` prompt** finds candidate studies with `brapi_find_studies` `variables` before reading observations, and reads text matches past the top 10 through `textMatchRank`. The published `brapi-guide` skill (1.1) gives the same guidance.

## Fixed

- **`brapi_submit_observations`** sends the singular `studyDbId` when reading `/variables` for its study variable review, which SGN servers honor where they ignore the plural. ([#122](https://github.com/cyanheads/brapi-mcp-server/issues/122))
- **Finders** count a row that several GET combinations returned once in `rowsScanned` and in stop warnings, and `brapi_find_variables` leaves `totalCount` off a multi-study union that stopped early. ([#123](https://github.com/cyanheads/brapi-mcp-server/issues/123))
- **Season labels** use one rule on `brapi_find_observations` (distributions, rows, the `seasons` filter), `brapi_germplasm_performance`, and `brapi_build_phenotype_matrix`: the `seasonDbId`, else name and year, else name, else year. SGN year-only seasons now label. ([#124](https://github.com/cyanheads/brapi-mcp-server/issues/124))
- **`brapi_get_study`** and the `brapi://study` resource resolve program, trial, and location through `GET /{noun}/{id}` when the server lists it, and through a list filter otherwise. A record the server doesn't return is omitted with a warning naming the noun and ID. ([#125](https://github.com/cyanheads/brapi-mcp-server/issues/125))
- **`brapi_find_locations`** `countryNames` search alpha-2, ISO numeric, and E.164 calling codes beside alpha-3 on SGN-family servers. A row matched only by a numeric code is dropped when its `countryName` names another country, and kept with a warning when it doesn't resolve. ([#126](https://github.com/cyanheads/brapi-mcp-server/issues/126))
- **`brapi_find_variables`** `text` gives every fetched match a `textMatchRank` in `results[]` and the dataframe, and reports `textMatchCount`. Every match leads `results[]` in rank order; `ontologyCandidates` stays the top 10. ([#127](https://github.com/cyanheads/brapi-mcp-server/issues/127))
- **`brapi_export_genotype_matrix`** rows are call sets, led by `callSetDbId`, `callSetName`, and `germplasmDbId`. The germplasm resolves through the call set's sample (paged `/callsets`, then `POST /search/samples`; Breedbase from `additionalInfo.germplasmDbId`) within the companion timeout, and is null with a warning when unresolved. ([#128](https://github.com/cyanheads/brapi-mcp-server/issues/128))
- **SGN `/studies`** receives `germplasmDbIds` as the singular `germplasmDbId`, so germplasm-scoped study reads, including `brapi_get_germplasm` `studyCount`, narrow on Sweetpotatobase.
- **`brapi_get_study` and `brapi_get_germplasm`** count a collection the server lists without `methods`.
