# 0.9.0 — 2026-10-17

## Added

- **`brapi_walk_pedigree` `diagram`** (`mermaid` | `dot`) returns the walk as diagram source in a `diagram` field ([#10](https://github.com/cyanheads/brapi-mcp-server/issues/10)); a diagram past 50,000 characters, or a Mermaid one past 500 edges, is omitted with a warning.
- **First-use connections** — an alias with a configured URL (`BRAPI_<ALIAS>_BASE_URL`, `BRAPI_DEFAULT_BASE_URL`, or an enabled builtin) registers on its first tool call instead of failing `unknown_alias` ([#59](https://github.com/cyanheads/brapi-mcp-server/issues/59)). Tools and resources declare the connect-time reasons `auth_token_exchange_failed`, `auth_no_access_token`, `capability_discovery_unavailable`, `upstream_unauthorized`, `upstream_forbidden`, `alias_base_url_invalid`, and `private_address_blocked`.
- **`brapi_dataframe_query` error reasons** `sql_execution_error`, `missing_table`, and `register_as_clash`, in place of untyped database errors.

## Changed

- **Breaking: `brapi_dataframe_query` refuses `current_setting`, `current_schema`, `current_schemas`, `in_search_path`, and `query_table`**, which 0.8.1 answered, as `sql_rejected` with `data.gateReason: denied_function`. `read_duckdb`, `parquet_full_metadata`, and `parquet_bloom_probe` now fail `denied_function` too, and a table reference that names a file or URL fails `sql_read_only`; 0.8.1 already refused those as `plan_operator_not_allowed`. DuckDB now runs with external access off (mcp-ts-core 0.13.15).
- **`brapi_find_*` inline `results[]`** stops at `loadLimit` or a 24,000-byte budget, whichever binds first; the matched rows beyond it are staged as a dataframe, and the notice names the dataframe tools that read it ([#66](https://github.com/cyanheads/brapi-mcp-server/issues/66), [#50](https://github.com/cyanheads/brapi-mcp-server/issues/50)). The prompts `brapi_eda_study` and `brapi_meta_analysis` follow.
- **Upstream calls share one 50 s deadline** per tool call, including the token exchange, retries, and polls ([#82](https://github.com/cyanheads/brapi-mcp-server/issues/82)). A call past it fails as `Timeout` with `data.reason: call_deadline_exceeded`, and a timed-out attempt is retried (up to `BRAPI_RETRY_MAX_ATTEMPTS`) only while the deadline fits another attempt.
- **ID and filter inputs** reject an empty or whitespace-only string at the schema (`-32602`) instead of sending it upstream, where it widened a filter or malformed a path. The free-text `text` inputs of `brapi_find_germplasm` and `brapi_find_variables` reject whitespace-only text and still read `''` as no filter.
- **`brapi_dataframe_query` `preview`** above 1,000 returns rows up to the row ceiling instead of being rejected ([#73](https://github.com/cyanheads/brapi-mcp-server/issues/73)).
- **`brapi_dataframe_describe`** lists dataframes on a shared HTTP endpoint when the request has a session-scoped canvas (`BRAPI_SESSION_ISOLATION=true`) ([#71](https://github.com/cyanheads/brapi-mcp-server/issues/71)).
- **`brapi_find_studies` `locations`** is applied client-side when the dialect drops `locationDbIds` on `/studies`, with a warning ([#65](https://github.com/cyanheads/brapi-mcp-server/issues/65)).
- **Genotype tools** name where a `variantSetDbId` comes from (`brapi_raw_get` on `/variantsets`) ([#78](https://github.com/cyanheads/brapi-mcp-server/issues/78)).
- **Server-owned output-schema descriptions** are shortened, and a test holds the default catalog's total under 52,000 bytes in `tools/list` ([#69](https://github.com/cyanheads/brapi-mcp-server/issues/69)).
- **`BRAPI_CANVAS_MAX_ROWS`** above `CANVAS_DEFAULT_ROW_LIMIT` fails startup; the canvas would otherwise reject every query.
- **Framework changes reaching callers and operators:**
  - 0.13.12: every call logs under a generated `requestId`, with the client's JSON-RPC id as `jsonRpcId`; URLs in errors and logs name only their origin.
  - 0.13.13: error envelopes no longer carry `data.rootCause`.
  - 0.13.14: tool-argument pre-validation also repairs numeric and boolean strings, a lone string for an array, and `null` optionals; the `-32602` rejection is capped at 10 issue lines.
  - 0.13.15: canvas SQL gate and engine hardening (see the breaking bullet); `@modelcontextprotocol/server` ^2.3.1.

## Fixed

- **`brapi_build_phenotype_matrix` and `brapi_germplasm_performance`** page past the first page when the server ignores `germplasmDbId` ([#61](https://github.com/cyanheads/brapi-mcp-server/issues/61)), report an upstream failure per study instead of "No observations found" ([#62](https://github.com/cyanheads/brapi-mcp-server/issues/62)), and report a study scan that stopped early — at `loadLimit`, the page cap, or a failed, empty, or repeated page — as truncated.
- **`brapi_build_phenotype_matrix` `extraFilters`** are checked against the returned rows; contradicted or unverifiable filters are named in `warnings` ([#81](https://github.com/cyanheads/brapi-mcp-server/issues/81)).
- **CassavaBase `/locations` filters** are no longer rewritten to singular keys the server ignores ([#63](https://github.com/cyanheads/brapi-mcp-server/issues/63)).
- **`brapi_walk_pedigree` `direction: both`** walks ancestors upward and descendants downward only, lists each parent–child pair once, and marks only loop-closing edges `isCycle` ([#64](https://github.com/cyanheads/brapi-mcp-server/issues/64)).
- **`brapi_find_germplasm` `text`** scans the remaining result set after a first-page miss when it fits the walk ceiling ([#68](https://github.com/cyanheads/brapi-mcp-server/issues/68)).
- **`brapi_find_*` `warnings`** render under a `**Warnings:**` heading, apart from Applied Filters ([#70](https://github.com/cyanheads/brapi-mcp-server/issues/70)).
- **`brapi_dataframe_query`** keeps a file-reference rejection in the `sql_rejected` contract ([#72](https://github.com/cyanheads/brapi-mcp-server/issues/72)).
- **Capability discovery** that timed out or failed transiently is no longer cached as a server with no services; the call fails `capability_discovery_unavailable` and retries on the next call ([#74](https://github.com/cyanheads/brapi-mcp-server/issues/74)).
- **`brapi_find_*` spill walks** continue past a short page when the upstream reports a larger total, and a dataframe is marked truncated only when it holds fewer rows than that total ([#75](https://github.com/cyanheads/brapi-mcp-server/issues/75)).
- **A spill whose row filter keeps no rows** returns no dataframe instead of failing in the canvas ([#79](https://github.com/cyanheads/brapi-mcp-server/issues/79)).
- **Malformed `BRAPI_*` config** fails startup with a configuration error behind the framework's config banner, not a raw stack at import ([#80](https://github.com/cyanheads/brapi-mcp-server/issues/80)).
