# 0.8.0 — 2026-09-23

## Added

- **`nextToolSuggestions`** on the orientation envelope (`brapi_connect`, `brapi_server_info`, `brapi://server/info`) — the entry-point finders the server can serve (`brapi_find_studies`, `brapi_find_germplasm`, `brapi_find_variables`, `brapi_find_locations`, in that order), each with `args: { alias }`. A finder counts when its GET route or a POST `/search` route the active dialect doesn't disable is advertised ([#57](https://github.com/cyanheads/brapi-mcp-server/issues/57)).

## Changed

- **Auth walls fail `brapi_connect`** — an HTTP 401/403 on `/serverinfo` or `/calls` throws `upstream_unauthorized` (-32006) / `upstream_forbidden` (-32005) with a credentials hint and caches nothing, instead of registering an empty profile ([#52](https://github.com/cyanheads/brapi-mcp-server/issues/52)).
- **Upstream 4xx carry an `upstream_*` reason** — 401/403/404 as `upstream_unauthorized` / `upstream_forbidden` / `upstream_not_found`, 429 as `upstream_rate_limited` (still retried), every other 4xx as `ValidationError` (-32007) `upstream_bad_request`. 408 and 425 stay `Timeout` and keep retrying ([#52](https://github.com/cyanheads/brapi-mcp-server/issues/52)).
- **A failed `brapi_connect` registers nothing** — token exchange and a fresh capability fetch run before the connection is saved, so a failure leaves any previous registration under the alias and its cached profile intact. `ServerRegistry.register()` is now `resolve()` + `save()`.
- **`baseUrl` with userinfo (`user:password@host`) is refused** with a `ValidationError` that does not echo the URL.
- **`discoverConfiguredAliases`** reports the `authMode` an argument-free `brapi_connect` would resolve to under the pairing rules below, including default credentials for an alias on `BRAPI_DEFAULT_BASE_URL`.

## Removed

- **Built-in aliases `t3-wheat`, `t3-oat`, `t3-barley`** — the Triticeae Toolbox hosts now require login. The registry keeps `bti-cassava`, `bti-sweetpotato`, and `bti-breedbase-demo` ([#52](https://github.com/cyanheads/brapi-mcp-server/issues/52)).

## Fixed

- **`brapi_describe_filters`** escapes backslashes before pipes in Description cells, so a `\|` in a filter description no longer splits the Markdown table row ([#55](https://github.com/cyanheads/brapi-mcp-server/issues/55)).
- **Capability and reference-data cache keys** hash the base URL (SHA-256) instead of mapping punctuation to `-`, so servers whose URLs differ only in punctuation no longer share cached entries.
- **Built-in attribution and the demo note** attach only when a built-in alias still points at its built-in URL.
- **Built-in alias lookup** matches every spelling that shares the alias's `BRAPI_<ALIAS>_*` env prefix (case, `_` for `-`), including entries in `BRAPI_BUILTIN_ALIASES_DISABLED`.

## Security

- **Caller-supplied credentials are no longer shared across session-less callers** — on an HTTP deployment with `MCP_AUTH_MODE=none` and `BRAPI_SESSION_ISOLATION=true`, `brapi_connect` refuses caller `auth` from a request with no MCP session (`auth_session_required`, before any token exchange). Keyless connects and operator env credentials still work ([#49](https://github.com/cyanheads/brapi-mcp-server/issues/49)).
- **Operator env credentials are only sent to the base URL configured with them** — per-alias credentials pair with `BRAPI_<ALIAS>_BASE_URL`, else the alias's enabled built-in URL; a caller `baseUrl` that differs is refused with `auth_base_url_mismatch` before any request. `BRAPI_DEFAULT_*` credentials attach only when the resolved URL is `BRAPI_DEFAULT_BASE_URL`. URLs compare after normalizing host case, default port, and trailing slashes.

## Dependencies

- `@types/node` ^26.5.1 → ^26.6.2

## Migration

- **T3 aliases** — set `BRAPI_<ALIAS>_BASE_URL` plus credentials for the host (e.g. `BRAPI_WHEAT_BASE_URL=https://wheat.triticeaetoolbox.org/brapi/v2` with `BRAPI_WHEAT_USERNAME` / `BRAPI_WHEAT_PASSWORD`), then connect with that alias.
- **`BRAPI_DEFAULT_*` credentials** are no longer inherited by an alias whose URL points at another server — give that alias its own `BRAPI_<ALIAS>_*` credentials.
- **Per-alias credentials with no URL of their own** (including leftovers for a built-in disabled via `BRAPI_BUILTIN_ALIASES_DISABLED`) are refused with `alias_base_url_unset` (-32008) — set `BRAPI_<ALIAS>_BASE_URL` or remove the credential variables.
- **A caller `baseUrl` that differs from a credentialed alias's configured URL** is refused with `auth_base_url_mismatch` — omit `baseUrl`, or register the other server under a different alias.
- **Upstream HTTP 400** now surfaces as -32007 `upstream_bad_request` (was -32602); clients routing on the code should switch to `data.reason`.
