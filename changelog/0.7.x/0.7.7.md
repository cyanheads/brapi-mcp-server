# 0.7.7 — 2026-07-15

## Added

- **`GENOTYPE_CALLS_MAX_PULL_CEILING`** — exported from `src/config/server-config.ts` (500,000). Bounds both the `genotypeCallsMaxPull` config max and `brapi_export_genotype_matrix`'s `maxCalls` input, so the advertised input range and the deployment ceiling cannot drift apart. ([#45](https://github.com/cyanheads/brapi-mcp-server/issues/45))
- **Supply-chain install guard** — `bunfig.toml` gains `minimumReleaseAge = 259200` (a 3-day hold on freshly published versions; existing `bun.lock` entries are unaffected) with `minimumReleaseAgeExcludes = ["@cyanheads/mcp-ts-core"]`, plus `[install.security] scanner = "@socketsecurity/bun-security-scanner"`. Configuring a scanner disables Bun's auto-install.
- **`.github/SECURITY.md`, `.github/FUNDING.yml`, `.gitattributes`** — disclosure policy, funding metadata, and LF normalization with `linguist-generated` markers on `bun.lock`, `CHANGELOG.md`, and `docs/tree.md`.

## Changed

- **`@cyanheads/mcp-ts-core`** `^0.10.9` → `^0.10.14`. Picks up the supply-chain guard and `oven/bun:1.3.14` Dockerfile pin with BuildKit install-cache mounts ([0.10.13](https://github.com/cyanheads/mcp-ts-core/blob/main/changelog/0.10.x/0.10.13.md)); the Docker build stage's `--ignore-scripts`, a definition-linter null guard, and canvas `importFrom` carrying `reason: 'missing_table'` ([0.10.14](https://github.com/cyanheads/mcp-ts-core/blob/main/changelog/0.10.x/0.10.14.md)); canvas not-found errors carrying `reason: 'canvas_not_found'` plus a recovery hint ([0.10.12](https://github.com/cyanheads/mcp-ts-core/blob/main/changelog/0.10.x/0.10.12.md)); the changelog `security` flag scoped to source-code fixes ([0.10.11](https://github.com/cyanheads/mcp-ts-core/blob/main/changelog/0.10.x/0.10.11.md)); and the js-yaml v4 → v5 migration ([0.10.10](https://github.com/cyanheads/mcp-ts-core/blob/main/changelog/0.10.x/0.10.10.md)).
- **`renderDistributions`** — takes the caller's `DataframeHandle` directly instead of a projected `{ truncated, rowCount, totalCount }` object, so a capped line can name the dataframe holding the omitted entries.
- **`collectPassthroughParts`** — accepts an optional trailing `DataframeHandle`. The `get_*` detail tools pass nothing: their records are not in a dataframe.
- **`devcheck` Outdated gate** — a row bun reports as held by `minimumReleaseAge` (Update equal to Current, marked `*`) is no longer a finding; a genuine update still fails the gate. `typescript` added to the outdated allowlist.
- **Twelve `skills/<name>/SKILL.md` re-synced** from the framework — `add-tool` 2.15→2.16, `api-canvas` 1.7→1.9, `api-linter` 1.7→1.8, `api-utils` 2.3→2.4, `api-workers` 1.5→1.6, `code-simplifier` 1.1→1.2, `design-mcp-server` 2.18→2.20, `git-wrapup` 1.4→1.7, `orchestrations` 1.4→1.6, `polish-docs-meta` 2.9→2.11, `release-and-publish` 2.9→2.11, `techniques` 0.1→0.2 — mirrored into `.claude/skills/` and `.agents/skills/`.
- **`package.json` packaging** — `author` set to `Casey Hand <casey@caseyjhand.com> (https://caseyjhand.com)`; `packageManager` bun@1.3.11 → bun@1.3.14.

## Removed

- **`truncationMeta`** — dropped from `find-helpers.ts`; `renderDistributions` now reads the handle's `truncated`/`rowCount`/`totalCount` itself.

## Fixed

- **Capped `find_*` renders pointed content-only clients at `structuredContent`** — a surface those clients cannot read. Oversized passthrough values and capped distributions now name the spilled dataframe and `brapi_dataframe_query` as the retrieval path, falling back to `structuredContent` only when no dataframe exists. `renderDistributions`'s hardcoded top-5 cap is replaced by a 400-character line budget, so a distribution that fits renders complete instead of dropping values at a scale that cost nothing to show. ([#41](https://github.com/cyanheads/brapi-mcp-server/issues/41))
- **`brapi_export_genotype_matrix` honored a caller `maxCalls` above the deployment ceiling** — the pull is now clamped to `min(maxCalls, genotypeCallsMaxPull)` with the effective cap reported in `warnings`, and the input schema rejects anything above `GENOTYPE_CALLS_MAX_PULL_CEILING`. `maxCalls` bounds the generated matrix, so an unclamped override also sized the `vcf`/`ped`/`map` text and the canvas table. ([#45](https://github.com/cyanheads/brapi-mcp-server/issues/45))
- **`brapi_export_genotype_matrix` truncated the variant column legend at 20 entries** — the legend is the only decoder from a sanitized column name back to its variant ID and has no describe or re-call path behind it, so it now renders complete. The VCF/PLINK preview notice names the matrix dataframe as a content-visible path to the genotypes, disclosing that it carries no CHROM/POS/REF/ALT coordinates, and now renders outside the fenced block rather than inside it. The preview cap itself stays: a skewed input can drive one serialization to ~16MB. Partially resolves [#42](https://github.com/cyanheads/brapi-mcp-server/issues/42) — the render-side loss is closed; the unbounded `columnCount` behind it is tracked in [#46](https://github.com/cyanheads/brapi-mcp-server/issues/46).
- **Docker `HEALTHCHECK` probed with `curl`, which `oven/bun:*-slim` does not ship** — a container reported `unhealthy` for its whole lifetime while serving correctly, failing any orchestrator gating on container health. Replaced with a bun-native `fetch` probe. ([#44](https://github.com/cyanheads/brapi-mcp-server/issues/44))
- **`renderDataframeHandle`** — the `columns` list is budgeted to one line and points at `brapi_dataframe_describe` for the full schema, bounding a wide genotype-matrix pivot. `renamedColumns` stays uncapped: it is the sole decoder for its mapping.
- **`brapi_submit_observations` apply mode returned `elicit_unavailable` on every client** — `ctx.elicit` was undefined at runtime, so the confirmation gate failed closed even for elicitation-capable clients and steered callers toward `force: true`. Fixed upstream in mcp-ts-core 0.10.3 ([cyanheads/mcp-ts-core#211](https://github.com/cyanheads/mcp-ts-core/issues/211)) and settled here by the `^0.10.14` adoption — no change to this server's code. ([#38](https://github.com/cyanheads/brapi-mcp-server/issues/38))
