# 0.7.13 — 2026-09-19

## Added

- **`server.json` lists the hosted endpoint** — `https://brapi.caseyjhand.com/mcp` is now a `streamable-http` remote; the README already documented the public instance.

## Changed

- **Session mode declared in `src/index.ts`** (`sessionMode: { default: 'stateful', require: 'stateful' }`). An HTTP start with `MCP_SESSION_MODE` unset still serves `stateful`; an HTTP start with `MCP_SESSION_MODE=stateless` now fails at startup with a `ConfigurationError` naming the conflicting value, instead of serving a mode under which the `brapi_submit_observations` confirmation round trip cannot be answered by a 2025-era client. stdio starts are never refused. The Docker image, the README env row, and `.env.example` already pinned `stateful`; `.env.example` now sets the line actively rather than as a comment (mcp-ts-core 0.13.1).
- **Tool error text** — `content[]` for a tool error now closes with `(reason <reason>)`, plus ` · not retryable` when `data.retryable` is `false`; `structuredContent` is unchanged (mcp-ts-core 0.13.5, [cyanheads/mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)).
- **Argument rejections** carry `data.reason: "invalid_arguments"` and a `Recovery:` hint naming the keys the tool accepts; an omitted required enum field now renders as missing rather than as a wrong choice (mcp-ts-core 0.13.3, [cyanheads/mcp-ts-core#445](https://github.com/cyanheads/mcp-ts-core/issues/445), [#378](https://github.com/cyanheads/mcp-ts-core/issues/378)).
- **Advertised `outputSchema`** — the `error.data.reason` description now terminates each declared entry with a period; the only `tools/list` difference from 0.7.12 (mcp-ts-core 0.13.5, [cyanheads/mcp-ts-core#389](https://github.com/cyanheads/mcp-ts-core/issues/389)).
- **Repo tooling** — 33 `errors[]` entries gain `thrownBy: 'service'` (lint-only metadata; entries stay advertised and thrown identically); `.github/CODE_OF_CONDUCT.md` and `.github/workflows/codeql.yml` added; `package.json` gains `funding` and ships `AGENTS.md`; `.codex-plugin` category set to `research`; `devcheck.config.json` gains the template's `outdated`/`lint` keys; `.env.example` documents the resumability, GC-pressure, and log-rate-limit vars (mcp-ts-core 0.13.6).

## Fixed

- **`SIGTERM`/`SIGINT` end the process explicitly**, exiting 0 once shutdown settles (mcp-ts-core 0.13.1, [cyanheads/mcp-ts-core#435](https://github.com/cyanheads/mcp-ts-core/issues/435)).
- **`brapi-client`'s upstream requests** now pass the per-attempt signal `withRetry` hands each attempt into the fetch call. With no retry deadline configured that signal is still the caller signal, as before — this still aborts on caller cancellation (mcp-ts-core 0.13.4, [cyanheads/mcp-ts-core#455](https://github.com/cyanheads/mcp-ts-core/issues/455)).

## Security

- **The SQL comment stripper the canvas read-only gate runs over every `brapi_dataframe_query` statement is a linear-time scan instead of a polynomial-time regex**, so a crafted query can no longer pin the event loop (mcp-ts-core 0.13.1, [cyanheads/mcp-ts-core#431](https://github.com/cyanheads/mcp-ts-core/issues/431)).
- **Tool-argument copying can no longer be re-prototyped by a caller's own `__proto__` key** (mcp-ts-core 0.13.4).
